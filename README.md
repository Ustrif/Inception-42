# Description

This project aims to broaden knowledge about system administration by using docker. This project focuses on dockerizing services like NGINX, WordPress and MariaDB into separate docker containers that communicate and work in sync within a custom docker network and volume, orchestrated with Docker Compose.

## Virtual Machines vs. Docker
- **Virtual Machines:** A hypervisor (like VMware, VirtualBox, or Hyper-V) emulates physical hardware. Each VM runs a complete Guest Operating System on top of virtual hardware, making VMs large and resource-heavy.

- **Docker:** The Docker Engine sits directly on top of the host operating system. Containers share the Host OS Kernel and isolate only the application processes, binaries, and libraries, making them lightweight and fast.

## Secrets vs. Environment Variables
- **Environment Variables:** Stored in `.env` files. They are easy to use but can be insecure if visible in process listings. Do not push it to public.

- **Docker Secrets:** Secure mechanism for storing and managing sensitive data—such as passwords, API keys, TLS certificates, and SSH keys—so they aren't hardcoded into images or exposed in environment variables.

## Docker Network vs. Host Network
- **Host Network:** Docker removes network isolation between the container and the Docker host, allowing the container to share the host's networking namespace directly.

- **Docker Network (Bridge):** Docker's default networking mode. It creates an isolated, private virtual network on your host machine, acting like a software router that connects containers together while keeping them separate from the outside world.

## Docker Volumes vs. Bind Mounts
- **Bind Mounts:** Directly links a specific file or directory on your host machine to a path inside a Docker container. Both the host and the container share the exact same files in real time—any changes made on one side are immediately reflected on the other.

- **Docker Volumes:** This is the preferred mechanism for persisting data generated by and used by Docker containers, completely managed by Docker itself. Unlike bind mounts, volumes are stored in a dedicated, isolated part of the host filesystem (e.g., /var/lib/docker/volumes/) rather than a user-specified directory, ensuring that data survives even after a container is deleted or recreated.

# Instructions

## Prerequisites
- **OS:** Linux (Ubuntu preferred)
- **Tools:** Docker Engine, Docker Compose, Make

### Installation & Execution
1.  **Clone the repository:**
    ```bash
    git clone <repository_url> Inception
    cd Inception
    ```

2.  **Configure Host:**
    Map the domain name to your local IP address in the `/etc/hosts` file. This means you can access website with login.42.fr instead of writing ip address.
    ```bash
    sudo nano /etc/hosts
    # Add the following line:
    127.0.0.1   login.42.fr
    ```

3. **Create `.env` file:**
   Create a `.env` file inside the `srcs/` directory with your own credentials (note: `WP_ADMIN_USER` must not contain `admin` or `administrator`):
   ```bash
   cat << 'EOF' > srcs/.env
   DOMAIN_NAME=login.42.fr
   WP_TITLE=Inception
   DATA_PATH=/home/login/data

   SQL_DATABASE=inception
   SQL_USER=your_db_user
   SQL_PASSWORD=your_db_password
   SQL_ROOT_PASSWORD=your_root_password

   WP_ADMIN_USER=your_admin_user
   WP_ADMIN_PASSWORD=your_admin_password
   WP_ADMIN_EMAIL=your_admin@student.42.fr

   WP_USER=your_user
   WP_USER_EMAIL=your_user@student.42.fr
   WP_USER_PASSWORD=your_user_password
   EOF
   ```

4.  **Build and Run:**
    Launch the setup using the Makefile located at the root.
    ```bash
    make
    ```

5.  **Access:**
    - **WordPress Website:** Open `https://login.42.fr` in your browser. (Replace `login` with your actual 42 login. Ignore SSL warnings for self-signed certificates.)

### Management
- **Up containers:** `make up`
- **Stop containers:** `make stop`
- **Down containers:** `make down`
- **Start containers:** `make start`
- **Clean up (Stop + Remove containers, networks, images & volumes):** `make fclean`
- **Rebuild:** `make re`
